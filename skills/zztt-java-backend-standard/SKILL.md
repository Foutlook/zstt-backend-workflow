# ZZTT Java Backend Standard

## 使用模式

先根据调用方式选择一种模式，不混合交付边界：

| 模式 | 进入条件 | 主要动作 | 交付 |
|---|---|---|---|
| 编写模式 | 用户明确要求按本规范编写或修改 Java 后端代码 | 读取目标代码和项目约束，只应用与当前改动相关的规范并验证 | 代码改动与验证结果 |
| 评审模式 | 用户明确要求按本规范评审代码 | 只读核对完整目标文件、必要调用方、测试和 diff | 带证据的问题或“未发现可操作问题” |
| 内部引用模式 | `zztt-implementation` 或 `zztt-code-review` 读取本 Skill | 在调用方当前阶段内执行规范检查 | 回写调用方主产物，不创建独立阶段产物 |

## 执行流程

1. 确认使用模式、用户指定范围和明确不改范围。
2. 读取项目 `AGENTS.md`、目标文件完整上下文和当前模块既有写法。
3. 按下列章节只检查本次范围实际涉及的规则；需要示例时读取 `references/java-backend-guidelines.md`。
4. 编写模式实施最小改动并验证；评审模式保持只读；内部引用模式遵守调用方阶段门禁。
5. 按模式交付：
   - 编写模式：实际修改、应用规则、验证命令与结果、未验证边界；
   - 评审模式：结论及问题位置、失败条件、影响、证据和最小修正方向；
   - 内部引用模式：将检查项、风险和验证证据回写调用方主产物。

## 停止与确认

- 编写模式发现需要改变接口、JSON 契约、数据范围、异常、事务、并发或兼容行为，而用户没有明确要求时，先说明证据、影响和最小决策点，等待确认后再实施。
- 评审模式只报告问题；用户明确要求修复后，才切换到编写模式并重新冻结范围。
- 内部引用模式发现与调用方上游产物或阶段边界冲突时，停止并交回调用方处理，不用本规范覆盖业务口径。
- 无法执行关键验证时，标明未验证范围和建议命令，不给通过结论。

## 优先级

1. 用户要求和项目 `AGENTS.md` 等项目约束；
2. 当前模块、文件和真实调用链的局部一致性；
3. 本团队规范；
4. 通用风格建议。

不要为了套规范重写无关历史代码。需要具体示例时读取 `references/java-backend-guidelines.md`。

## 代码与注释

- 改动范围必须追溯到当前需求或评审问题。
- 保留既有注释，不删除、重写或清理与当前改动无关的注释。
- 非平凡的业务边界、状态转换、顺序保证、数据来源、事务后动作和异常兜底必须解释“为什么”。
- 注释不逐行翻译代码；简单 getter、常量和一层方法调用保持直接，不为形式抽取局部变量。
- 主方法优先展示业务步骤；只在复杂、复用或便于调试时抽取中间结果。

## JavaBean 与 Jackson

- 把首段单字母或第二个字符大写的字段视为高风险，例如 `zValue`、`pType`、`uId`、`eTag`、`aName`。
- 高风险字段显式声明规范 JSON 名称：`@JsonProperty("zValue")`。
- 只有历史请求确实需要兼容时才使用 `@JsonAlias`，别用 alias 代替规范属性名。
- 修改此类 DTO 时使用 ObjectMapper 或 MVC 请求测试证明序列化和反序列化名称正确。
- 排查缺参时先区分“请求未发送”和“Jackson 未绑定”。

## 数据访问与远程调用

- 禁止 N+1。列表、批量、聚合和循环处理先收集参数，再批量查询、预加载或批量远程调用。
- 禁止在循环中按单 ID 调用 Mapper、Repository、RPC、HTTP 或外部 API，避免循环远程调用。
- 查询只取所需列，明确分页、排序、逻辑删除、租户和权限范围。
- 聚合接口使用单一关系源确定最终实体集，再从同一范围派生 ownership、章节、状态和响应映射。
- 不用 fallback 或平行数据源掩盖实体范围不一致。

## 接口、异常与事务

- 参数校验与业务校验分层清晰，异常保留有用上下文但不泄漏敏感信息。
- 不吞异常，不只打印 message；链路关键失败记录业务身份、动作和下游结果。
- 事务边界围绕一致性要求，不把无依据的慢远程调用放进事务。
- 接口、RPC、MQ、枚举、错误码和 DTO 演进写清兼容策略。

## 验证

- 新行为和缺陷修复优先使用失败测试驱动；验证至少覆盖主路径和本次风险边界。
- Maven 项目若 smart-doc 绑定 compile/test 等早期生命周期，业务验证传 `-Dsmart-doc.phase=verify`，不要为绕过一次本地失败修改项目默认阶段。
- 无法运行验证时说明具体边界、未验证风险和建议命令，不写成已通过。

## 提交边界

ZZTT 固定工作流不自动 commit、push、合并或部署。用户明确要求提交时，Git commit message 使用中文。
