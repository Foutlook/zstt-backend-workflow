# 现有功能分析高级手册

## 1. 最小问题卡

开始时只锁定会改变答案的内容：

- 具体功能问题和用户可见入口；
- 目标读者；
- 产品、模块、接口或数据边界；
- 已知仓库、版本、路由、类、字段、业务 ID 或其他锚点；
- 是否明确要求变更影响；
- 仅在运行证据必要时使用的唯一环境、身份和时间窗口。

用户已经提供的信息直接使用，不重复提问。缺失项不会改变当前答案时保留为未知，不为了补齐表格阻塞分析。

## 2. 代码来源门禁

按以下优先级选择唯一代码来源：

1. 用户明确给出一个或多个本地仓库路径时，验证仓库身份并只读取这些路径。本次不得检查私有 MCP 配置或切换远程仓库。
2. 用户未给本地路径时，才检查项目受 Git 忽略的私有仓库 MCP 配置是否完整；只判断完整性，不回显值。
3. 配置完整且当前会话实际暴露匹配的只读仓库 MCP 时，通过 MCP 读取远程代码；配置中的 URL 不能作为普通 HTTP 地址调用。
4. MCP 不可用时，只使用当前已授权且身份明确的本地仓库上下文、CodeGraph、`rg` 和逐层源码阅读。目标仓库仍无法确认时，索取精确路径或仓库身份，不猜目录。

记录最终使用的仓库、版本或提交、未覆盖仓库和索引新鲜度。候选仓库只表示允许读取，不代表功能一定在其中实现。

## 3. 当前行为取证

按问题选择最短路径：

- 页面或接口条件：入口、鉴权/校验、业务状态、响应字段最终赋值；
- 数据来源：调用链、最终 Mapper/SQL/远程接口、过滤和映射范围；
- 状态流转：生产方、持久化、事务边界、消息/缓存传播和消费者；
- 外部副作用：RPC、MQ、Job、通知、缓存、ES 和 after-commit 行为；
- 能力开关：配置来源、作用范围、默认值和运行绑定。

只把必经路径或有直接证据的分支纳入当前行为。负面结论需要给出仓库版本、搜索范围、查询词、已检查命中和未覆盖范围；一个零命中不能证明某能力不存在。

## 4. 环境特定证据

运行日志、数据库或部署状态只有在它们会改变答案时才读取。锁定一个 `test` 或 `prod` 环境，使用项目 `.zstt-kit` 已配置的受限 Scope；生产配置缺失时不能回退到测试。

有 Trace ID 时先查 Trace 和失败 Span，再按服务与分钟级窗口查询日志；没有 Trace ID 时使用业务 ID、接口、服务和有限时间窗口收敛。MySQL 和 ES 查询只选择必要字段、稳定排序并限制数量。任何输出都必须脱敏。

把“代码可达”“本次实际执行”“数据库存在该状态”和“由多项事实推断”分别标注。运行证据不足时保持当前静态结论和运行时缺口，不把静态路径写成已发生事实。

## 5. 功能模型

功能答案只保留与问题相关的元素：

| 元素 | 要回答的问题 |
|---|---|
| 触发 | 谁在什么条件下进入功能 |
| 规则 | 哪些状态、权限、参数或配置真正改变结果 |
| 主流程 | 从入口到最终结果经过哪些必要边界 |
| 数据 | 最终读取、计算、赋值或写入来自哪里 |
| 例外 | 空数据、重复、并发、历史值和失败时怎样处理 |
| 副作用 | 是否写库、发消息、改缓存、调用外部服务 |
| 用户结果 | 最终可见行为是什么 |

事实不一致时说明冲突属于意图、实现、运行还是数据层，并说明它是否阻碍直接答案。

## 6. 变更影响

只有用户明确要求时才执行。以将改变的规则、接口、字段、状态或数据源为起点，检查：

- 直接调用方和下游消费者；
- DTO/JSON、RPC、MQ、缓存、ES 和数据库兼容；
- 历史数据、幂等、权限、事务和异步时序；
- 需要调整的测试、监控、灰度与回滚边界。

影响分析只说明可能受影响的现有边界和证据，不替代需求澄清、技术方案或任务拆分。

## 7. 交付与纠正

先给直接答案，再给最小流程、决定性证据、冲突和未知。用户纠正业务口径、仓库、版本或环境时，更新同一分析，不保留两个并行的当前结论。

只有用户明确要求留档时才使用报告模板。报告是本次派生分析，不得替代需求、调研、方案或架构的权威产物。
