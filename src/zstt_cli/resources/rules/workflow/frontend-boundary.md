# ZSTT 前后端职责与辅助验证

## 适用范围

ZSTT 以 Java 后端为实施和阶段验收范围。前端代码只作为辅助验证，不是后端流程的前置条件。需求澄清、任务拆分和文档检查只消费相关结论，不为执行本规则主动读取前端。

## 读取边界

- 仅在职责取舍、页面异常归因或接口消费者兼容核查有具体问题时，最小范围读取前端。沿相关页面事件、请求构造、接口调用、响应处理、展示或状态更新取证，不做全仓扫描。
- 前端代码只通过只读远程仓库 MCP 读取；不查找、要求或读取本地前端 checkout，不 clone、下载成仓库、建立 worktree、修改或执行前端代码。后端本地路径的来源限制只约束该后端仓库，不禁止远程前端辅助核查。
- 使用已有 Kit 的 `runtime/with_env.py <test|prod> repo-mcp` 注入凭据，再通过同一 Kit 的 `runtime/repo_mcp_client.py probe` / `explore` 调用只读 `codegraph_explore`。明确测试环境时使用 test，其他情况沿用既有 prod 默认；不跨环境重试。以客户端实际参数为准，不编造分支参数或绕过客户端使用 Web、curl、PowerShell、普通 HTTP、Git 下载代码。
- 从需求、后端调用契约或已确认仓库清单定位前端仓库，不猜同名项目。记录远程仓库、分支/ref、提交、文件与行号或符号、索引覆盖及局限；未返回的信息写“未取得”，不能声称已验证最新版本或实际部署行为。
- MCP 不可用、权限不足、仓库身份不明、版本无法核实或源码不完整时，停止该项辅助读取，记录“前端辅助验证未完成”及原因，继续后端工作；不要求用户提供本地前端代码，不反复探测或等待恢复。

## 职责判断

先拆开产品目标、现有后端能力、前端使用事实和建议分工。页面出现一个需求不等于需要新增接口；接口具备能力也不等于前端已使用。

| 约束 | 取舍依据 | 例子 |
|---|---|---|
| 展示和临时交互 | 已有接口提供所需完整、获准可见的数据时，优先前端处理 | 日期格式、展开收起、已加载完整列表的本地排序 |
| 可信业务结果 | 权限、租户隔离、持久化状态、金额和业务规则由后端最终校验 | 前端禁用提交按钮不能替代后端权限检查；前端金额预览不能作为结算真值 |
| 筛选、排序、统计 | 先证明数据范围、完整性、时效和传输代价 | 当前页排序不能满足全量排名；不能为了前端计算而返回越权明细或拉取无界全量数据 |
| 双方都可实现 | 在满足同一验收口径下，比较现有能力复用、跨端一致性、计算/传输成本和总改动成本 | 接口已提供状态与必要数据时，不为单页标签拼接新增接口 |

需求阶段不提前决定实现。差异分析只确认后端缺口与待核查分工；设计阶段在现有 `Dxx` 中记录选择、依据、后端是否需要变化、前端交接及验证方式；Quick 在现有范围和实现记录中表达，不额外建立台账或门禁。

允许“后端无需修改，建议前端承接”；这是分工建议，不是“前端已实现”。缺少前端证据时，基于已确认需求、后端代码与契约确定可证明的后端范围，把客户端现状留为未知；不为填补未知添加后端接口、字段、fallback 或重复规则。

## 阶段推进与交接

- 后端仓库的来源、基线、核心证据、SQL 和测试门禁仍有效；前端辅助仓库不套用本地来源回退、基线 P0、必需仓库完整覆盖或端到端验收门禁。
- 前端辅助证据缺失只进入现有产物的未验证边界或交接说明，不单独计为 P0、不强制草稿、不阻塞阶段完成、后端任务执行或后端交付。不为未知本身制造 P1/P2；具体风险才按影响分级。
- 每个需求仍保留追溯：分别写明后端已验证能力/改动与前端建议/未核查范围。只在后端结论闭环时声明后端完成，不能省略需求、伪造前端证据或把页面/端到端测试记为通过。
- 前端建议不进入后端代码改动落点、`Txx` 或执行依赖；在现有交接中写需求/决策来源、接口与字段、预期行为和核查动作。未确定负责人时写“前端负责人待对接”，不因此阻塞后端。
- 若已有可靠证据证明后端缺陷、安全问题或真实契约冲突，按原门禁处理具体问题；“辅助验证不阻塞”不能豁免已证实的问题。前端确需配合发布时如实交接，但辅助读取失败本身不是发布依赖。
