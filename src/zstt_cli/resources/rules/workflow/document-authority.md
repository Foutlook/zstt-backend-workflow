# ZSTT 文档权威与纠正规则

## 1. 权威主产物

每个固定阶段只有一份权威主产物。用户、阶段 Skill、辅助工具和并行子任务都必须把当前结论汇总回该文件，不能创建 `final-v2`、`新版` 或另一个方案作为替代权威来源。

主产物负责保存：

- 当前阶段结论和状态；
- P0/P1/P2 或 Review 问题数量；
- 关键证据、设计决定和风险；
- 辅助附件索引；
- 用户确认和纠正后的最新口径；
- 下游交接信息。

## 2. auxiliary 附件

`auxiliary/` 可以保存详细证据和可复用附件，例如：

- `claim-ledger.md`；
- `interface-details/`；
- `schema.sql` 或 SQL 草案；
- `review-rounds/`；
- `test-runs/`；
- `tool-capabilities.md`。

附件不能独立宣称阶段完成。主产物必须写明附件路径、摘要和最终结论；附件与主产物冲突时，以主产物为准并同步修正附件。

## 3. 用户纠正

用户纠正需求、代码事实、方案或测试口径时：

1. 明确指出被纠正的旧结论和新事实；
2. 找到当前结论所属的权威主产物；
3. 直接回写相关章节、问题计数和确认记录；
4. 标出受影响的下游产物和需要重新验证的结论；
5. 重新运行当前阶段 `complete-stage`；内容指纹变化会先撤销该阶段及下游旧完成状态。

不要只在聊天中承认纠正，也不要只追加一条互相矛盾的备注。

## 4. 上游回写

下游阶段发现需求、调研或设计存在冲突时，必须上游回写：

- 需求口径错误或缺失，回写 `00-requirement.md`；
- 代码事实、调用链或数据源错误，回写 `01-research.md`；
- 接口、SQL、状态或发布方案改变，回写 `02-design.md`；
- 执行顺序、文件范围或验证方式改变，回写 `03-tasks.md`。

完成上游回写和重新校验之前，不在下游增加 fallback、替代字段或平行方案掩盖冲突。

## 5. 并行结果汇总

并行子任务和专项审查只产生候选结论。主上下文负责：

- 验证文件位置、调用链、失败条件和测试结果；
- 去除重复或互相矛盾的结论；
- 将确认后的内容写入权威主产物；
- 把详细原始记录按需放入 `auxiliary/`；
- 拒绝未经主上下文复核的完成声明。

## 6. 推进边界

- 更新附件不得自动推进阶段。
- 用户纠正不得绕过 `prepare-stage` 或 `complete-stage`。
- 子任务、工具或附件不得自动修改 `meta.json`。
- 当前阶段结束后只能推荐下一阶段，不得自动推进或自动执行推荐项。
