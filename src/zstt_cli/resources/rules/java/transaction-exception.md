# 接口、异常与事务规则

## 触发条件

本次范围会改变接口/RPC/MQ 契约、异常语义、事务、持久化或外部副作用。

## 强约束

- 参数校验与业务校验分层，异常保留定位上下文但不得泄漏敏感信息。
- 不吞异常，不只记录 `message`；链路关键失败应保留业务身份、动作和下游结果。
- 事务边界围绕一致性要求，不把没有依据的慢 RPC、HTTP 或消息等待放进事务。
- 接口、RPC、MQ、枚举、错误码和 DTO 演进必须写清兼容策略。
- 修改异常类型、重试次数、超时、事务提交时机或通知顺序都可能改变业务行为，必须显式评估并审批。

## 例子

把“事务提交后发事件”改成“事务内发事件”，可能让消费者读到未提交数据。即使代码更短，也不能当作行为保持型重构直接实施。
