# Java 注释规则

## 强约束

- 保留既有注释；不删除、改写或“清理”与当前请求无关的注释。
- 移动代码时同步移动描述该逻辑的注释；行为不变时保留原意和必要历史背景。
- 非平凡业务边界、状态转换、顺序保证、数据来源、事务后动作、异常兜底和兼容逻辑必须解释“为什么”。
- 注释不要逐行翻译代码，也不要给简单 getter、明显赋值或普通循环增加噪声。
- 只更新本次逻辑真正发生变化的注释，避免顺手统一措辞。

## 例子

需要保留或补充：`// 事务提交后再发消息，避免消费者读取到尚未提交的数据。`

不需要增加：`// 获取用户 ID` 紧邻 `request.getUserId()`。
