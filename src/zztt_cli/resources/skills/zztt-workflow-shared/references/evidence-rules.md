# ZZTT 证据规则

## 证据等级

| 等级 | 含义 |
|---|---|
| Proven | 由真实代码、schema、SQL、配置或可复现命令直接证明，并记录仓库、文件、行号或符号。 |
| Framework inferred | 由框架约定连接，但运行时 Bean、配置、环境或生成产物仍可能改变结果。 |
| Requirement claim | 来自需求材料或用户说明，尚未由代码验证。 |
| Runtime dependent | 必须依靠运行配置、日志、Trace、消息、远程服务或真实环境才能证明。 |
| Unknown | 当前证据缺失、冲突或工具不可用。 |

## Claim Ledger

重要结论使用 Claim Ledger（结论账本）记录，保证下游能区分已证明事实和待验证假设。最小字段为：

| 字段 | 要求 |
|---|---|
| 结论 ID | 当前需求内唯一、可稳定引用的编号。 |
| 结论 | 一条可验证的陈述，不把多个判断混成一条。 |
| 证据等级 | Proven、Framework inferred、Requirement claim、Runtime dependent 或 Unknown。 |
| 代码位置 | 仓库、文件、行号或符号；非代码证据记录材料和位置。 |
| 反证 | 搜索过但不支持结论的路径、冲突材料或相反运行结果。 |
| 置信度 | 高、中、低，并解释限制条件。 |
| 运行时缺口 | 静态材料不能证明的配置、数据、消息、权限或远程状态。 |
| 验证动作 | 将结论提升为 Proven 所需的具体命令、日志、接口或人工确认。 |

结论变化时更新原条目，并记录变化原因；不要保留两条互相冲突且都标为当前事实的记录。

## 结论规则

- 先定位直接失败点或最终行为点，再追真实调用链。
- 追到最终查询、计算、赋值或持久化位置，记录真正影响结果的关键参数。
- Guard 条件只说明是否允许继续，不自动等于真实业务依赖。
- 重要结论必须能从证据索引反查，不能只写类名或“代码如此”。
- 静态代码不能证明运行时事实。需要环境证据时明确记录缺口和验证动作。
- 对聚合、列表、图表和映射补全，先核对最终实体集和映射数据是否来自同一范围。
- 不用 fallback、替代字段、平行查询或新分支掩盖数据源或口径冲突，除非证据证明它是业务要求。
